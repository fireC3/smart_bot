# SmartBot 架构设计文档

## 1. 概述

SmartBot 是一个基于 Python 的 AI Agent 编排系统，支持多模型提供商、可扩展工具链、事件驱动钩子和灵活的会话管理。核心设计目标是**模型与业务解耦**、**工具可插拔**、**交互可配置**。

### 1.1 设计原则
1. **抽象优先**：所有 AI 能力通过标准接口 (`LLM`) 访问，业务逻辑不依赖具体 SDK。
2. **流式原生**：LLM 调用全链路支持流式输出。
3. **工具可插拔**：工具通过注册机制自动发现，权限系统统一管理。
4. **事件驱动**：Hook 系统在会话/工具调用的关键节点触发自定义逻辑。
5. **交互无关**：前端通过 `ChatFrontend` 协议抽象，支持 CLI 和 WebSocket。

## 4. 核心架构

### 4.1 分层架构

```
┌─────────────────────────────────────┐
│            Frontend                  │  CLI / WebSocket（ChatFrontend 协议）
├─────────────────────────────────────┤
│           Pipeline                   │  对话编排（MainChatPipeline）
├─────────────────────────────────────┤
│    LLM    │   Tools    │   Hooks    │  核心能力
│    ─────  │   ─────    │   ─────    │
│  DeepSeek │  File*     │  BashHook  │
│  DashScope│  Bash      │  HttpHook  │
│  Ollama   │  Browser   │  ...       │
├─────────────────────────────────────┤
│            Config                    │  配置管理（JSON 持久化）
└─────────────────────────────────────┘
```

### 4.2 核心数据流

```
User Input
    │
    ▼
ChatFrontend (CLI / WebSocket)
    │
    ▼
MainChatPipeline.run_chat_turn()
    │
    ├─► LLM.invoke() — 流式生成回复
    │     │
    │     ├─► TextBlock / Thinking → 前端输出
    │     ├─► ToolCallBlock → 权限检查
    │     │     ├─► ALLOW → 加入执行队列
    │     │     ├─► CONFIRM → 用户确认
    │     │     └─► DENY → 拒绝
    │     └─► UsageBlock → 用量统计
    │
    └─► ToolManager.execute_tool()
          │
          ├─► Hook: TOOL_CALL_BEFORE
          ├─► Tool.run()
          └─► Hook: TOOL_CALL_AFTER / TOOL_CALL_FAILED
```

### 4.3 会话生命周期

```
MainChatState.build()
  ├─ 解析平台配置
  ├─ 初始化 LLM 实例
  ├─ 加载 Skills
  ├─ 初始化 ToolManager
  ├─ 构建系统提示词
  ├─ Hook: SESSION_START
  ├─ LLM.enable()
  └─ 进入对话循环...
      └─ MainChatState.destroy()
           ├─ Hook: SESSION_END
           └─ LLM.disable()
```

## 5. 模块详解

### 5.1 接口层 (Interface)

#### 5.1.1 LLM 抽象基类

```python
class LLM(ABC):
    async def enable(self)          # 初始化客户端
    async def disable(self)         # 清理客户端
    async def invoke(messages, tools) -> AsyncGenerator[ContentBlock]
    async def get_available_models() -> List[str]
```

所有平台必须实现 `invoke()`，生成 `ContentBlock`（TextBlock, ToolCallBlock, UsageBlock 等）。

#### 5.1.2 消息系统

消息模型基于 `ContentBlock` 的列表而非纯文本，支持多模态内容：

- **TextBlock**: 文本内容，可选 thinking/reasoning_content
- **ImageBlock**: 图片（URL 或 Base64）
- **ToolCallBlock**: 工具调用
- **UsageBlock**: 令牌用量统计

消息类型：`UserMessage`, `AIMessage`, `SystemMessage`, `ToolMessage`

#### 5.1.3 工具系统

```python
class BaseTool(ABC):
    name: str
    description: str
    parameters: list[ToolParameter]
    permission: ToolPermission  # ALLOW / CONFIRM / DENY
    async def run(arguments, context) -> str
```

- 工具通过 `@ToolManager.register_tool` 装饰器注册
- 自动发现：`ToolManager` 在初始化时扫描 `tools/` 目录下的所有 `.py` 文件
- 权限模式：`DENY_ALL` / `STRICT` / `DEFAULT` / `ALLOW_WRITE` / `ALLOW_BASH` / `ALLOW_ALL`
- 大结果自动截断并保存到临时文件

### 5.2 平台层 (Platforms)

当前支持的 LLM 平台：

| 平台 | 模块 | API 兼容 | 特性 |
| :--- | :--- | :--- | :--- |
| **DeepSeek** | `deepseek.py` | OpenAI SDK | 文本、图片、工具调用、thinking/reasoning |
| **DashScope** | `dashscope.py` | OpenAI SDK | 文本、图片、工具调用、thinking/reasoning |
| **Ollama** | `ollama.py` | Ollama SDK | 本地模型、工具调用、thinking |

平台注册表在 `platforms/utils.py` 中维护，新增平台只需添加映射并在 `platforms/` 下创建实现文件。

### 5.3 Hook 系统

Hook 系统在关键事件节点插入自定义逻辑：

**事件类型**:
- `SESSION_START` / `SESSION_END` — 会话生命周期
- `TOOL_CALL_BEFORE` / `TOOL_CALL_AFTER` / `TOOL_CALL_FAILED` — 工具调用

**动作类型**:
- `BashHookAction` — 执行 shell 命令（环境变量 `HOOK_EVENT`、`HOOK_ARGUMENTS` 传递上下文）
- `HttpHookAction` — 发送 HTTP POST 请求

**特性**:
- `block_on_failure`: 失败时是否阻断后续流程
- `match_tool`: 仅匹配特定工具的调用事件
- 超时控制：默认 30 秒

### 5.4 配置管理

配置存储在 `~/.config/smart_bot/` 下，使用 JSON 文件：

| 文件 | 内容 |
| :--- | :--- |
| `platforms.json` | 多平台配置（provider、base_url、api_key、模型列表、能力覆盖） |
| `settings.json` | 全局设置（默认平台、默认模型、数据目录、额外 skill 路径） |
| `hooks.json` | Hook 配置 |

顶层 `ConfigManager` 为单例，统管三个 Store。

### 5.5 前端抽象

`ChatFrontend` 协议定义了一组异步方法，用于解耦 I/O：

- `output_text()` / `output_thinking()` — 输出文本/思考内容
- `output_tool_call()` / `output_tool_result()` — 输出工具调用及结果
- `output_usage()` — 输出令牌用量
- `request_tool_confirmation()` — 请求工具执行确认
- `request_user_input()` — 请求用户输入

两个实现：`CLIFrontend`（交互式终端）和 `WebSocketFrontend`（FastAPI WebSocket）。

### 5.6 Web 服务

FastAPI 应用提供 REST API：

- `GET /api/models` — 列出所有可用模型
- `GET /api/providers/defaults` — 获取提供商默认配置
- `GET/POST/DELETE /api/platforms` — 平台 CRUD
- `POST /api/platforms/connection-test` — 测试连接
- `POST /api/platforms/fetch-models` — 拉取模型列表
- `GET/PUT /api/settings` — 设置管理
- `GET/PUT /api/hooks` — Hook 管理
- `WebSocket /ws/chat` — WebSocket 对话端点

## 6. 权限安全模型

### 6.1 工具权限

每个工具有三种权限状态：
- **ALLOW** — 自动允许执行
- **CONFIRM** — 需要用户确认
- **DENY** — 禁止执行

### 6.2 权限模式

| 模式 | 说明 |
| :--- | :--- |
| `DENY_ALL` | 全部拒绝 |
| `STRICT` | 严格模式（所有需确认的工具默认拒绝） |
| `DEFAULT` | 默认模式（需确认的工具需用户批准） |
| `ALLOW_WRITE` | 允许写操作 |
| `ALLOW_BASH` | 允许 bash 执行 |
| `ALLOW_ALL` | 全部允许 |

## 7. 扩展指南

### 7.1 添加新 LLM 平台

1. 在 `src/smart_bot/platforms/` 下创建新文件（如 `openai_compat.py`）
2. 继承 `LLM` 基类，实现 `invoke()`、`enable()`、`disable()`、`get_available_models()`
3. 定义 `default_config` 类变量（`PlatformConfig` + `ModelCapability`）
4. 在 `platforms/utils.py` 中添加 `PROVIDER_MODULE` 和 `PROVIDER_CLASS` 映射
5. 在前端或直接修改 `platforms.json` 配置文件

### 7.2 添加新工具

1. 在 `src/smart_bot/tools/` 下创建新文件
2. 继承 `BaseTool`，设置 `name`、`description`、`parameters`、`permission`
3. 使用 `@ToolManager.register_tool` 装饰器注册
4. 实现 `run()` 方法

### 7.3 添加 Hook

在 `~/.config/smart_bot/hooks.json` 中添加配置：

```json
{
  "session_start": [
    {"action": {"type": "BashHookAction", "cmd": "echo 'Session $HOOK_EVENT started'"}, "timeout": 10}
  ],
  "tool_call_before": [
    {"action": {"type": "HttpHookAction", "url": "http://localhost:8080/webhook"}, "block_on_failure": false, "match_tool": ["bash"]}
  ]
}
```
